Agent Reliability asks a slightly impolite question: when an agent says "done," what actually happened?

This is an ongoing project, currently at v0.1 alpha. I expect to keep returning to it as agent architectures, failure modes, and the industry's tolerance for cheerful uncertainty continue to evolve.

The harness runs agents inside a controlled local world, introduces the sorts of failures that demos politely avoid, and checks the full trajectory. Did the task succeed? Did the agent stay inside its authority? Did it recover safely? Did its final claim match the world state? How much did the whole adventure cost?

Phase 1 includes 24 scenarios covering ambiguity, permission limits, prompt injection, poisoned tools, duplicate side effects, rate limits, stale state, memory poisoning, evaluator tampering, false completion, shutdown behavior, and other ways autonomy can become an incident report.

Every failed assertion points back to trace events, state differences, a failure class, and an exact replay command. The goal is not to award agents a vague gold star. It is to give builders evidence they can use to make the next engineering decision.
